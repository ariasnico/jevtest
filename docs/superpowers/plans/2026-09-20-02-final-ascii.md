# Final ASCII de Caramelo — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. No delegar sin una elección explícita del usuario.

**Goal:** Entrar al boliche y recibir una invitación a bailar como recompensa visual.

**Architecture:** Victoria autoritativa del servidor y secuencia visual independiente. Recursos generados previamente; reproducción local sin nuevas llamadas a IA.

**Tech Stack:** HTML/CSS/JS, GPT Image integrado, node:test y Playwright para E2E.

**Spec:** [Diseño aprobado, sección B](../specs/2026-09-20-caramelo-design.md).

## Global Constraints

- Arte ASCII con GPT Image; animación de 6 FPS; movimiento reducido y omitir secuencia.
- No agregar frameworks ni un segundo juego dentro del boliche.
- Móvil primero: 320 px como ancho mínimo; entrada de 16 px y objetivos táctiles de 44 px.
- No publicar, desplegar ni contratar servicios con esta tarea de planificación.

### Task 1: estados de victoria sin tapar la última frase

**Interfaces:** `nextEnding(state,event)` retorna estado; estados/eventos abajo.
`createEnding({scene,onRestart}) -> {admit,start,skip,reset,destroy}` controla DOM.

- [ ] Test fallido inicial:

```js
test('ganar no inicia automáticamente la película',()=>{
  assert.equal(nextEnding('door','WIN'),'admitted');
  assert.equal(nextEnding('admitted','ENTER'),'entering');
  assert.equal(nextEnding('entering','SKIP'),'invitation');
  assert.equal(nextEnding('invitation','RESTART'),'door');
});
```

- [ ] Implementar función pura con mapa explícito; eventos inválidos dejan estado:

```js
const transitions = {
 door:{WIN:'admitted'}, admitted:{ENTER:'entering'},
 entering:{ARRIVE:'inside',SKIP:'invitation'},
 inside:{INVITE:'invitation',SKIP:'invitation'},
 invitation:{FINISH:'complete'}, complete:{}
};
export function nextEnding(state,event) {
 return event==='RESTART'?'door':transitions[state]?.[event]??state;
}
```

- [ ] Cambiar render de won: mantener burbuja final y ofrecer botón «Entrar».
  Loss conserva final actual. Integrar createEnding; ninguna transición visual
  envía solicitudes que modifiquen estado de juego.
- [ ] Ejecutar `node --test test/ending.test.mjs`, verificar doble ENTER e invalid
  ARRIVE desde door, y commit de máquina de estados y pruebas.

### Task 3: reproducción, accesibilidad y fallos

`reset/destroy` cancelan todos los timers y devuelven el arte de la puerta.

- [ ] Reproducir con reloj activo de 6 FPS; pausar al ocultarse la pestaña, sin
  avanzar ocho segundos de golpe al volver. Cada tick consume un holdFrame;

- [ ] Escena invitation muestra HTML con texto exacto: «Vení, tenemos lugar en la

- [ ] Añadir control explícito de pausa a motion.js al salir de door/admitted;

Task 1 conserva diálogo; Task 2 produce arte real; Task 3 reproduce, permite omitir
y recupera fallos. El final depende únicamente del contrato won, no del proveedor
de diálogo ni del alojamiento público.
