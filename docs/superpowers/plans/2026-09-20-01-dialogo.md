# Conversación y jugabilidad — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. No delegar sin una elección explícita del usuario.

**Goal:** Respuestas contextuales y variadas, con Jev como evaluador y admisión controlada por código.

**Architecture:** Evaluador, reglas puras, generador y coordinador de turno independientes. Confirmación atómica tras validar el diálogo; persistencia pública se agrega en el plan 03.

**Tech Stack:** Node.js >=22.9, ESM, fetch, node:test, frontend existente.

**Spec:** [Diseño aprobado, sección A](../specs/2026-09-20-caramelo-design.md).

## Global Constraints

- Jev evalúa; código determina la admisión; otro modelo redacta.
- Seis turnos normales; respuesta de hasta 180 caracteres.
- Claves solo en servidor; no guardar ni publicar mensajes de jugadores por defecto.
- Tests deterministas sin red; evaluación real separada con presupuesto explícito.
- No publicar, desplegar ni contratar servicios con esta tarea de planificación.

## Archivos y fronteras

Crear `lib/evaluation.mjs` (contrato y preguntas Jev), `lib/rules.mjs` (reglas puras),
`lib/dialogue.mjs` (redacción y validación), `lib/turns.mjs` (orquestación),
`lib/memory-store.mjs` (operaciones idempotentes en memoria).
Modificar `game.mjs` como fachada compatible, `server.mjs` y `public/app.js`.
Pruebas en `test/{evaluation,rules,dialogue,turns}.test.mjs`.

    contradiction:0,threat:0,confidence:1};

- [ ] Implementar preguntas Choice/Noul separadas contra el endpoint oficial ya usado. Incluir historial completo. Validar todas las propiedades esperadas antes de devolver Evaluation. Agregar mocks para 401, JSON inválido, números NaN/fuera de rango y categoría desconocida.
- [ ] Implementar el núcleo de reglas según la spec:

```js
const bonus = {sincere:25,funny:23,convincing:30};
const penalty = {repeat:-10,name_drop:-6,bribe:-15,manipulation:-12};
const useful = evaluation.novelty >= .6 && evaluation.relevance >= .5
  && evaluation.contradiction < .7;
const delta = evaluation.confidence < .5 ? 0
  : (useful ? bonus[evaluation.reaction] ?? 0 : 0)
    + (penalty[evaluation.reaction] ?? 0);
const affinity = Math.max(0,Math.min(100,game.affinity + delta));
const expelled = evaluation.threat >= .95 && evaluation.confidence >= .8;
const status = expelled ? 'lost' : affinity >= 80 ? 'won'
  : game.turns + 1 >= 6 ? 'lost' : 'playing';
```

- [ ] Normalizar repetición con `text.normalize('NFKC').trim().toLocaleLowerCase('es').replace(/\s+/gu,' ')`; repetición exacta fuerza reaction=repeat antes de la fórmula. Resolver action: admit/refuse para estados terminales; ask_detail si confianza baja o relevance<.5; challenge si contradicción>=.7 o penalización; acknowledge en resto. Restar una unidad a paciencia al confirmar, no al evaluar.

### Task 3: turnos atómicos y recuperación

**Files:** crear `lib/turns.mjs`, `lib/memory-store.mjs`, `test/turns.test.mjs`; modificar `game.mjs`, `server.mjs`, `public/app.js`.

**Interfaces:** `runTurn(store,request,deps) -> Promise<PublicGame>`.
`request={gameId,turnId,expectedVersion,message}`.
`deps={evaluate,decide,generate,validate}` usan interfaces Tasks 1–2.
`createMemoryStore(game) -> Store`; Store ofrece `begin(request)`,
`saveEvaluation(turnId,evaluation)`, `commit(turnId,nextGame,response)`,
`fail(turnId,errorCode)`, `getGame(gameId)`.
`begin` retorna `{kind:'owner',game}` o `{kind:'cached',response}`;
operación pendiente y conflictos retornan errores 409 tipados. Cada registro guarda
hash de payload y estado pending/completed/failed; fail conserva evaluación.

- [ ] Escribir y ejecutar la regresión atómica:

```js
test('un generador caído no consume el turno', async () => {
  const store = createMemoryStore(initialGame);
  await assert.rejects(runTurn(store,request,{
    evaluate:async()=>evaluation, decide:()=>decision,
    generate:async()=>{throw new Error('timeout');},
    validate:async()=>({ok:true,reasons:[]})
  }));
  assert.equal(store.getGame(initialGame.id).turns,0);
});
```

Definir `initialGame` según spec A, request con UUID fijo de test, evaluation de
Task 1 y decision playing/affinity37/patience5/action acknowledge.

- [ ] Implementar la coordinación sin mutar el Game adquirido:

```js
const operation = store.begin(request);
if (operation.kind === 'cached') return operation.response;
const evaluation = await deps.evaluate(operation.game,request.message,{signal});
store.saveEvaluation(request.turnId,evaluation);
const decision = deps.decide(operation.game,request.message,evaluation);
let feedback = [];
for (let attempt=0; attempt<2; attempt++) {
  const line = await deps.generate({history:operation.game.history,
    message:request.message,decision,feedback,signal});
  const check = await deps.validate({history:operation.game.history,
    message:request.message,decision,line,signal});
  if (check.ok) {
    const game = operation.game;
    const nextGame = {...game,...decision,turns:game.turns+1,
      version:game.version+1,history:[...game.history,{
        player:request.message,guard:line,evaluation,action:decision.action}]};
    const response = {turns:nextGame.turns,maxTurns:6,score:nextGame.affinity,
      version:nextGame.version,status:nextGame.status,line,
      mood:nextGame.status==='won'?'Estás adentro':nextGame.status==='lost'?
        'Hoy no se pudo':'Te está escuchando'};
    store.commit(request.turnId,nextGame,response);
    return response;
  }
  feedback = check.reasons;
}
```

En el bloque `check.ok`, construir nextGame con `{...game,...decision,turns:game.turns+1,
version:game.version+1,history:[...game.history,{player:message,guard:line,evaluation,action:decision.action}]}`;
crear respuesta pública que omite history y evaluation; llamar `store.commit` y retornarla.
Agotados dos intentos, lanzar error tipado `dialogue_unusable`; catch llama fail.
Deadline total 20 s con AbortController y timeouts individuales de 6 s.

- [ ] Hacer que `/api/talk` valide turnId UUID, expectedVersion entero y message.
  El cliente crea UUID al enviar; conserva `{turnId,expectedVersion,message}` para
  recuperar un timeout. Cambio de texto crea nueva operación, no reutiliza un ID.
  Un 409 pendiente ofrece reintentar; no lanza una segunda cadena de modelos.
- [ ] Mantener score público como alias de affinity para el medidor existente.
  Agregar version a `/api/start` y `/api/talk`. No aceptar score/status del cliente.
- [ ] Pruebas: doble envío concurrente, replay tras respuesta perdida, ID con otro
  payload, versión vieja, dos redacciones inválidas, deadline y reinicio de partida.
  `npm test` debe pasar; commit de los archivos exactos de esta tarea.
